# 🎫 AI Support Ticket Extractor: Fine-tuned LLM for English & Arabic

A small language model (**Qwen2.5-1.5B-Instruct**) fine-tuned with **LoRA** to turn messy customer messages, in English, Arabic dialects (Egyptian, Gulf, MSA) and Franco-Arabic, into clean, structured support tickets.

```
"الأوردر رقم ١٢٣٤٥ لسه موصلش وأنا محتاجه بكرة ضروري"
```
```json
{
  "intent": "delivery_delay",
  "order_id": "12345",
  "sentiment": "neutral",
  "urgency": "high",
  "language": "ar"
}
```

## Why this is useful

Support teams receive hundreds of unstructured messages a day. Extracting the intent, order number, sentiment and urgency automatically lets a business:

- **Route** tickets to the right team (billing, delivery, returns…)
- **Prioritize** angry or urgent customers first
- **Feed** CRMs, dashboards, and automations (n8n, Zapier) with clean data

A small fine-tuned model does this **cheaply, privately** (it can run on the company's own server), and **consistently**, including dialects and Franco-Arabic that general models often get wrong.

## Output schema

| Field | Values |
|---|---|
| `intent` | `delivery_delay`, `refund_request`, `return_exchange`, `cancel_order`, `payment_issue`, `damaged_product`, `account_issue`, `general_question` |
| `order_id` | Order number as a string with Western digits (`"٤٥٢١"` → `"4521"`), or `null` |
| `sentiment` | `positive`, `neutral`, `negative` |
| `urgency` | `low`, `medium`, `high` |
| `language` | `en`, `ar`, `mixed` (Franco-Arabic or Arabic + English) |

## Data

| Split | Size | Source |
|---|---|---|
| Train | 900 | Synthetic: generated by [`data/generate.py`](data/generate.py) |
| Validation | 100 | Synthetic, same generator |
| **Test** | **60** | **Hand-written separately**, with different wording from the training templates |

The generator combines hand-written templates (per intent and dialect) with realistic variation: greetings, angry or thankful tones, urgency phrases, typos and lowercase text, Arabic-Indic digits (`٤٥٢١`), and order formats like `#4521`, `ORD-88213` and `رقم الطلب`.
Language mix: about 50% English, 35% Arabic, 15% mixed. A unit test checks that **no test message leaks into training**.

### Labeling rules

To keep labels consistent, sentiment and urgency follow fixed rules:

- **sentiment:** `negative` if the message is a complaint or the tone is annoyed or angry; `positive` if the customer is thankful (and not complaining); otherwise `neutral`.
- **urgency:** `high` if the customer asks for a fast reply ("ASAP", "ضروري", "bsor3a") or is angry; `medium` if the sentiment is negative; otherwise `low`.

## How it works

| Step | Details |
|---|---|
| Base model | `Qwen2.5-1.5B-Instruct` (multilingual, small enough for a free GPU) |
| Method | LoRA (r=16) on attention and MLP layers, with [Unsloth](https://github.com/unslothai/unsloth) for faster training |
| Training | 3 epochs, lr 2e-4, cosine schedule, loss on the JSON answer only |
| Hardware | Free Google Colab T4 GPU, about 20 minutes |

## Run it yourself

**Train:** open [`train_colab.ipynb`](train_colab.ipynb) in Google Colab, select a T4 GPU and choose **Run all**.

**Demo locally:**
```bash
pip install -r requirements.txt
MODEL_ID=your-hf-name/ticket-extractor-qwen1.5b python app.py
```

**Tests:**
```bash
pip install pytest transformers
pytest
```

## Limitations

- Training data is synthetic. Real customer messages are messier, so for production you would add a few hundred real, labeled messages from the business.
- The test set is small (60 messages), so treat the results as indicative, not a benchmark.
